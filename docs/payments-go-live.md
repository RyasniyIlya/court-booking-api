# Онлайн-оплата: перевірка перед запуском клубу

Гроші йдуть на рахунок клубу (його мерчант у mono, LiqPay чи WayForPay). Kort їх не торкається, тож лицензія НБУ не потрібна.

## Чотири рівні перевірки

| Рівень | Що перевіряє | Гроші | Як запустити |
|---|---|---|---|
| 1. Юніт- та роут-тести | підписи, статуси, суми, ідемпотентність на моках | немає | `npm test` (платіжні: `npx vitest run src/lib/payments src/routes/pay`) |
| 2. Приймальний скрипт, режим «без грошей» | справжній HTTP-API, справжні ключі клубу, справжня БД тестового клубу, підписані вебхуки | немає | `npm run test:payments:live` |
| 3. Приймальний скрипт, режим «живі гроші» | справжній банк: рахунок, оплата карткою, вебхук банку, повернення | 1 оплата + повернення | `PAYCHECK_REAL=1 npm run test:payments:live` |
| 4. Чек-лист запуску клубу | кабінет, віджет, каса, фіскалізація | немає | розділ нижче |

Рівень 2 перевіряє наш код і те, що ключі клубу вміє читати банк. Він **не** доводить, що банк достукається до вебхука. Це доводить тільки рівень 3.

## Змінні скрипта

```bash
PAYCHECK_CONFIRMED=yes             # так, це тестовий клуб і тестова БД
PAYCHECK_API_URL=https://...       # адреса API (типово http://localhost:3000)
PAYCHECK_CLUB_SLUG=test-club       # клуб із увімкненою передоплатою, провайдер обрано в кабінеті
PAYCHECK_PROVIDER=liqpay           # liqpay | wayforpay | mono
PAYCHECK_CREDENTIALS='{"publicKey":"...","privateKey":"..."}'
```

Формат `PAYCHECK_CREDENTIALS`:
- liqpay: `{"publicKey":"…","privateKey":"…"}`
- wayforpay: `{"merchantAccount":"…","secretKey":"…","domain":"…"}`
- mono: просто токен рядком

Скрипт читає `DATABASE_URL` з `.env`. Не запускайте його на проді й на клубі з живими гравцями: він створює й видаляє броні з телефонами `+38050…`.

## Що перевіряє режим «без грошей» (liqpay, wayforpay)

1. API відповідає, клуб видно публічно.
2. `PUBLIC_API_URL` публічний HTTPS.
3. Банк приймає ключі клубу (`testConnection`).
4. Бронь створює рахунок, сторінка оплати відкривається, приватний ключ у ній не світиться.
5. Підроблений підпис вебхука відхиляється (400), бронь лишається PENDING.
6. Вебхук для невідомого рахунку нічого не змінює.
7. Недоплата на 1 копійку не підтверджує бронь (платіж FAILED, `AMOUNT_MISMATCH`).
8. Повна оплата: бронь CONFIRMED, платіж PAID.
9. Повторний вебхук нічого не ламає, `paidAt` не змінюється.
10. Запізнілий `failed` після оплати не скасовує бронь.
11. Повернення: бронь CANCELLED, платіж REFUNDED.

## Важливо про sandbox

API навмисно відхиляє на `NODE_ENV=production` sandbox-ключі LiqPay (`sandbox_…`) та публічний мерчант WayForPay `test_merch_n1`: їхні підписи можна підробити. Тому:
- Sandbox-перевірку робимо локально або на staging, не на проді.
- На проді перевіряємо тільки справжніми ключами клубу й режимом 3.

## Режим «живі гроші» (рівень 3)

Це обов'язковий крок перед тим, як клуб почне приймати оплати. Він єдиний підтверджує весь ланцюг у банку.

1. Клуб підключає свій мерчант (договір з банком), вводить ключі в кабінеті під PIN власника, натискає «Перевірити підключення».
2. Тестова бронь на мінімальну суму (ціна корту в тестового клубу, наприклад 1–10 грн, залежно від мінімуму банку).
3. Запуск: `PAYCHECK_REAL=1 npm run test:payments:live`.
4. Скрипт друкує посилання, ви платите **справжньою карткою**, скрипт чекає вебхук до 10 хвилин.
5. Скрипт викликає повернення і чекає REFUNDED до 5 хвилин. Запис броні лишається як обліковий.
6. Для mono це **єдиний** спосіб перевірки: його вебхук підписує банк.

Якщо вебхук не прийшов за 10 хвилин: перевірте `PUBLIC_API_URL`, що API доступний ззовні, і логи API (`[pay] webhook rejected`).

## Чек-лист запуску клубу

- [ ] У клуба є договір еквайрингу, ключі лежать у кабінеті, «Перевірити підключення» зелене.
- [ ] `PUBLIC_API_URL` та `PAYMENTS_SECRET` на проді задані й **не змінюються** (інакше ключі клубів перестануть розшифровуватись).
- [ ] Режим 3 пройдений: реальна оплата, вебхук, повернення.
- [ ] Бронь, оплачена тестово, видна в касі клубу з правильною сумою.
- [ ] Політика скасування клубу видна гравцю до оплати.
- [ ] Клуб знає, що фіскальний чек (ПРРО) на його стороні. Перевірити вимоги до його форми оподаткування.
- [ ] Для «закінчення строку»: неоплачена бронь звільняє слот через `payHoldMinutes` (є юніт-тести, у режимі 3 можна перевірити руками, не оплативши рахунок).
- [ ] Клуб знає, що робити, якщо гроші списані, а броні немає: сповіщення «Оплата без запису» у Telegram, повернення в кабінеті.
- [ ] Вимкнення: у кабінеті клуб може зняти передоплату, не видаляючи ключі. Видалити ключі чи змінити провайдера не можна, поки є платежі PENDING чи PAID (так задумано).

## Що НЕ перевіряється автоматично

- Реальна 3DS-сторінка й вигляд checkout у банку.
- Затримки повернень (WayForPay може віддати «в обробці» до надходження коштів).
- Складні випадки Google/Apple Pay.
- Фіскалізація.

Їх перевіряє людина в режимі 3 і за чек-листом.
