# Проект: виджет бронирования кортов — контекст

## Модель проекта
Вариант B: не SaaS-подписка, а разовые внедрения. Продаём конкретному клубу
установку за 20–30 тыс. грн + 500 грн/мес за хостинг. Причина: весь рынок Украины —
300–500 клубов (падел ~200 кортов на ~50 клубов, теннис ~150–200, сквош — десятки),
подписная модель упирается в потолок 50–85 тыс. грн MRR при конкуренции с Appointer
и бесплатным EasyWeek. Проектные деньги при уже написанном коде — чистая маржа.

## Стек
Бек: Node + TypeScript + Express + Prisma + PostgreSQL + Zod + Luxon.
Фронт: React, без Tailwind и без UI-библиотек (виджет ставится на чужие сайты).

## Ключевые архитектурные решения (не переделывать без причины)
1. **Свободных слотов в базе нет.** Хранится только занятое — Booking и Block.
   Свободное вычисляется вычитанием из рабочих часов дня.
2. **Двойная бронь блокируется базой, а не кодом.** Перед записи нет проверки
   «свободно ли». Прилетает 23P01 → API отдаёт 409 → виджет перерисовывает сетку.
3. **Всё время в базе — timestamptz (UTC).** Рабочие часы — минуты от полуночи
   по локальному времени клуба, конвертация через Luxon от Club.timezone.
4. **clubId в админке берётся из JWT**, никогда из тела запроса. Обновления идут
   через updateMany({where: {id, clubId}}), чужая запись даёт count=0 → 404.
5. **Стили виджета изолированы** через `all: initial` и префикс `cb-`.
6. **Занятые слоты видны** (штриховка), а не скрыты — игрок видит свободное днём.

## Что не сделано
- Вывод остатка абонемента и поиска по цифрам в интерфейс админки (бек готов).
- Telegram-бот: привязка номера, напоминание за сутки, остаток абонемента.
- Автосписание занятия — ждём ответов с обзвона о правиле сгорания.
- Демо на реальном домене с сид-данными.
- Предоплата, SMS, Google Calendar.

## Решения по абонементам
- Регистрации клиента нет. Идентификатор — телефон, нормализованный к E.164.
- Телефон уникален внутри клуба, не глобально (один человек, два клуба).
- Имя из формы не перезаписывает карточку, исправленную админом.
- Каждое списание — запись PassUsage, откатывается одной кнопкой.
- Из нескольких активных абонементов берётся сгорающий раньше.
- Абонемент показывает админ в планшете, клиент ничего не предъявляет.
- QR-коды не делаем. Telegram — самообслуживание, не пропуск.
- Полную CRM (штат, зарплаты, склад, касса) не строим — там Appointer и YCLIENTS.

## Как продаём
Персональная демо-ссылка с логотипом клуба → встреча → вопрос про предоплату.
Скрипт разговора: чем пользуетесь сейчас, сколько платите, когда сможете внести
предоплату за внедрение под вас. Три отказа на слове «предоплата» из пяти
разговоров = ниша не подтвердилась.
